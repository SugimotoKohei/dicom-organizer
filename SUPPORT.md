## English

Thank you for using `dicom-organizer`. When you encounter questions or unexpected behavior, please follow the steps below in order.

### 1. Where to Look First

1. **Frequently Asked Questions**: Check [FAQ](docs/faq.md) for common error messages, unrecognized files, or platform notes.
2. **Documentation**: Browse the [Documentation Index](docs/README.md) for user guides, the [Support Matrix](docs/support-matrix.md), and [Deployment Guide](docs/deployment-guide.md).
3. **Discussions**: Search or post general questions and usage ideas on [GitHub Discussions](https://github.com/SugimotoKohei/dicom-organizer/discussions).
4. **Issue Tracker**: Search existing issues or open a [Bug Report](https://github.com/SugimotoKohei/dicom-organizer/issues/new?template=bug_report.yml) or [Scanner Verification Report](https://github.com/SugimotoKohei/dicom-organizer/issues/new?template=verification_report.yml).
5. **Direct Email Contact**: If you do not have a GitHub account or need to discuss non-public organizational matters, email `sugimotokouhei@gmail.com`.

### 2. CRITICAL WARNING: Do NOT Send Patient Data or DICOM Files

To protect patient privacy and comply with healthcare data regulations:
- **NEVER send real DICOM files, protected health information (PHI), patient names, patient IDs, or birth dates** via public Issues, Discussions, or email.
- **NEVER attach unredacted screenshots** showing patient identifiers or private institutional folder paths.
- If demonstrating a problem, use synthetic DICOM files (such as those generated by `--self-test` or `examples/synthetic_quickstart.py`).

### 3. Information to Include in Bug Reports

To help diagnose problems effectively, please inspect and provide the following sanitized information:

1. **Environment Diagnostics (`--diagnostics`)**:
   Run `dicom-organizer --diagnostics` (or in GUI: **Help → Copy Diagnostic Info**). This automatically masks home directory paths as `~` and reports Python, OS, and package versions without exposing personal files.
2. **Summary Counts from `organize_summary.json`**:
   Share the total count of files, processed series, and the counts under `skipped_by_reason`. Check beforehand that no private identifiers remain.
3. **Reason Counts from `file_report.csv`**:
   Summarize the counts of distinct `Status` and `Reason` codes. Do not attach the full `file_report.csv` if it contains private file names or clinical directory paths.
4. **Command Line or GUI Settings**:
   The exact arguments, layout mode, profile, and flags used (with file paths replaced by generic placeholders like `/path/to/input`).

### 4. Support Scope and Response Expectations

- **Volunteer Maintenance**: `dicom-organizer` is currently developed and maintained by a single primary maintainer during available volunteer time. There is no guaranteed response time or service-level agreement (SLA).
- **Security Vulnerabilities**: For responsible disclosure of security issues, please refer to [SECURITY.md](SECURITY.md).

<a id="japanese"></a>
## 日本語

`dicom-organizer` をご利用いただきありがとうございます。疑問点やトラブルが生じた際は、以下の順序でご確認・お問い合わせをお願いいたします。

### 1. 困ったときの調べ方（推奨する順序）

1. **よくある質問（FAQ）**: [FAQ](docs/faq.md) を確認してください。よくあるエラーメッセージ（未処理ファイル、既存フォルダ、未署名アプリの警告など）の対処法をまとめています。
2. **各種ドキュメント**: [ドキュメント目次](docs/README.md) から、利用ガイド、[対応範囲表](docs/support-matrix.md)、[施設導入ガイド](docs/deployment-guide.md) を参照してください。
3. **GitHub Discussions**: 使い方、アイデア、他ツール連携の相談は [GitHub Discussions](https://github.com/SugimotoKohei/dicom-organizer/discussions) に投稿してください。
4. **GitHub Issues**: ソフトウェアの不具合は [Bug Report](https://github.com/SugimotoKohei/dicom-organizer/issues/new?template=bug_report.yml)、実機検証の共有は [Verification Report](https://github.com/SugimotoKohei/dicom-organizer/issues/new?template=verification_report.yml) からご報告ください。
5. **メール窓口**: GitHub アカウントをお持ちでない方や、公にできないご相談は `sugimotokouhei@gmail.com` へご連絡ください。

### 2. 重要: 患者情報や実 DICOM ファイルを絶対に送らないでください

医療情報の安全管理およびプライバシー保護のため、以下の事項を厳守してください:
- **実際の DICOM ファイル、患者氏名・ID・生年月日などの患者情報（PHI）を、GitHub（Issue / Discussion）やメールに絶対に添付・記載しないでください。**
- **患者情報や施設の内部パスが写り込んだスクリーンショットを送信しないでください。**
- 不具合の再現には、`--self-test` や `examples/synthetic_quickstart.py` で作成される合成データをお使いください。

### 3. 報告に含めると役立つ情報

不具合を迅速に把握するため、事前に内容を確認したうえで以下の情報をお知らせください:

1. **環境診断情報 (`--diagnostics`)**:
   `dicom-organizer --diagnostics`（GUI の場合は「ヘルプ → 診断情報をコピー」）の出力。ホームディレクトリは自動で `~` にマスクされ、個人パスを含めずに OS・Python・ライブラリの版を取得できます。
2. **`organize_summary.json` の件数**:
   処理ファイル数、検出シリーズ数、`skipped_by_reason`（未処理理由の内訳）の件数。
3. **`file_report.csv` の理由別の件数**:
   各 `Status` や `Reason` が何件あったかの集計。ファイル名に患者情報や個人名が含まれる可能性があるため、CSV ファイル自体の添付は避けてください。
4. **実行コマンド・GUI 設定**:
   使用したプロファイル、レイアウト、オプション（パスは `/path/to/input` など伏字にしてください）。

### 4. サポートの範囲と対応方針

- **個人による保守**: 本プロジェクトは現在 1 名の保守者が個人の空き時間で開発・運営しています。返信や対応までの日数を保証するものではありません。
- **セキュリティ脆弱性**: 脆弱性の報告は [SECURITY.md](SECURITY.md) の手順に従ってください。
